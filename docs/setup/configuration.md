# Configuration
All user-tunable values live in YAML under `backend/config/`. Committed
**templates** end in `.example.yaml`, the application reads the **real**
`*.yaml` file next to each template. Real files are gitignored — you create
them once via `make config`, then edit them freely.

> ！Do not edit any `*.example.yaml` — they are read-only templates committed to git. You should edit only `*.yaml` files.

### 2.0 Layout
Configuration layout:

```
backend/config/
├── general.example.yaml      ┐
├── general.yaml              ┘  committed template + gitignored real file
├── evaluation.example.yaml
├── evaluation.yaml
├── mostly_ai.example.yaml
├── mostly_ai.yaml
├── rules.example.yaml
├── rules.yaml
└── pipelines/
    ├── *.example.yaml         committed pipeline templates
    ├── *.yaml                 user-editable real pipelines (gitignored)
    └── rules/
        ├── *.example.yaml
        └── *.yaml
```

### 2.1 `general.yaml`
Runtime tunables plus the per-run execution parameters used when invoking
`python -m backend.src.cli` directly.

* **`settings:`**
  - `enable_data_profiling`, `default_csv_delimiter`, `default_sample_size`.
* **`execution:`** — consumed by `make <mode>`:
  - `mode` (`i`/`t`/`s`/`e`), `file_paths`, `sample_size`, `model_id`,
    `simulation_id`, `inspection_id`.
* **How to change a value per-install:** edit
  `backend/config/general.yaml`. Example:
  ```yaml
  execution:
    simulation_id: "simulation_20260408_153348"
  ```
* **Finding IDs:** from within `.venv_core`:
  - **Inspections**: `python -m src.core.catalog.inspections --format table`
  - **Models**: `python -m src.core.catalog.models --format table`
  - **Simulations**: `python -m src.core.catalog.simulations --format table`

### 2.2 `mostly_ai.yaml`
Parameters passed to the deep learning architecture of Mostly AI.

* **What it Does:** Dictates engine parameters (e.g. `max_epochs`, `max_training_time`, `batch_size`) and privacy layers (`differential_privacy`).
* **`per_table`:** Any `model_settings` key can be overridden for a specific table. Useful for disabling DP on tables that form a deep context chain (see the [Documentación técnica](<../documentacion-completa/Documentación técnica 20260630.docx>) for this Mostly AI limitation).
* **When to Touch:**
  - You encounter RAM constraints and need to lower `batch_size`.
  - You require an expedited, low-quality test run so you lower `max_epochs: 1` or cap `max_training_time`.
  - You are experimenting with distinct Differential Privacy strictness.
  - Three or more related tables need DP disabled on the deeper ones.

### 2.3 `rules.yaml`
Logical validation rules mapped explicitly onto the datasets to restrict anomalies generated by ML models.

* **How to Setup Rules:**
  - Open `rules.yaml` and append objects to the `rules` array.
  - Define `type` (e.g., `date_inequality`, `semantic_ranking_consistency`).
  - Target your custom tables (`table_origin`, `table_target`) and map the constraint columns.
* **When to Touch:**
  - Every time you introduce a new table relationship or business rule that must not be violated by synthetic generation.

### 2.4 `evaluation.yaml`
All evaluation configuration in a single file: metrics, bootstrap/CI
parameters, and the per-column statistics list.

* **`metrics.default`**: list of metrics to calculate. Comment out heavy
  ones like `DomiasMIA_BNAF` while iterating.
* **`num_bootstrap_samples`**,
  **`average_complementary_tvd_n_bins`**: statistical knobs.
* **`metrics.tstr.target_column` / `task_type`**: TSTR performance metric
  configuration.
* **`statistics:`**: list of `{operation, table, col, ...}` entries
  describing baseline statistics (`mean`, `median`, `variance`, formulas
  like `np.log({col})`, or custom operations from
  `CUSTOM_STATISTICS_MODULE`). Each gets a bootstrap CI.

Non-YAML evaluation knobs live in `backend/src/config/evaluation.py`:
- `EVAL_PYTHON_PATH`: resolved from the `EVAL_PYTHON_PATH` env var or
  `.venv_eval/bin/python`.
- `CUSTOM_STATISTICS_MODULE`: resolved from the env var of the same name.
